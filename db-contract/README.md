# DB後方互換セーフティ（父親画面 凍結のための安全装置）

作成: 2026-06-22 ／ 関連: `開発部/ひかる商店独立化_作業手順書.md` リスク#1

## これは何か
将来、ひかる商店（父親）の管理画面を別リポジトリに**凍結コピー**したあとも、共通版と
同じデータベースに繋がる。だから共通版で**DBの形（項目・処理）を壊す変更**をすると、
凍結した父親画面が突然動かなくなる（過去に項目改名・関数引数変更で実際に壊した）。

このフォルダは、その事故を**事前に検知して止める**ための仕組み。

## 鉄則（add-only）
**DB変更は「追加」だけ。** 既存の項目/処理に対する以下は禁止：
- カラムの削除・改名・型変更・NOT NULL付け外し
- 関数(RPC)の削除・改名・引数変更・戻り値変更

どうしても変えたいときは「新カラム/新関数を足して、旧いものは残す」。

## ファイル
| ファイル | 役割 |
|---|---|
| `schema-baseline.psv` | DBの形の基準（凍結契約）。`kind\|obj\|member\|sig`。**人が手で消さない** |
| `snapshot-query.sql` | 現状のDBの形を同じ形式で取り出すクエリ（個人情報は読まない） |
| `check-compat.py` | 基準と現状を比べ、破壊的変更だけを警告するチェッカー |

## 使い方（migrationを当てる前に必ず）
1. `snapshot-query.sql` を Supabase で実行（スキーマのみ・Wata承認）
2. 返ってきた文字列を `db-contract/_current.psv` に保存
3. `python db-contract/check-compat.py` を実行
   - `[OK] 破壊的変更ナシ` → migrationを進めてよい
   - `[NG] 破壊的変更 N件` → **止める。** add-only に直す
4. `_current.psv` は使い捨て（gitに入れない）

## 意図的に項目を増やしたとき（基準の更新）
カラム/関数を**追加**したら（追加は安全）、基準も最新化しておく：
1. `snapshot-query.sql` を実行
2. 返り値を `schema-baseline.psv` のデータ部（`#`コメントより下）に置き換え
3. 「追加のみ」であることを `check-compat.py`（旧基準 vs 新基準）で確認してからコミット

## 注意
- これは**形（スキーマ）**の番人。データ中身は見ない。
- 父親を実際に凍結するのは「有料顧客1社獲得後」。この安全装置は**それまでの間も**、
  活発な共通版開発で父親の“生きている画面”を壊さないために有効。
